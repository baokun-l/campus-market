# 前后端接口对接问题清单

> 比对对象：
> - 前端：`实践任务2：Web前端开发(Vue3+Element Plus+ECharts)/campus-secondhand-frontend`
> - 后端：`实践任务3：后端开发(前后端分离)/campus-secondhand-backend`
>
> 比对方式：脚本自动提取前端 `src/api/*.ts` 中全部 `request({ url, method })` 调用，
> 与后端 9 个 Controller 的 `@GetMapping/@PostMapping/...` 映射逐条对比（路径参数归一化为 `{}`）。
>
> 生成日期：2026-09-16

---

## 一、总体结论

| 指标 | 数量 |
|---|---|
| 前端调用端点数 | **97** |
| 后端已实现端点数 | **85** |
| **前端在调、后端没实现** | **16** |
| 路径写法不一致（同一个功能） | **1** |
| 后端实现但前端未调用 | 3 |

**一句话**：后端的**分层架构、响应体格式、分页格式、错误码**与前端完全对齐，骨架没问题；
但有 **16 个接口后端没实现**、**1 个接口路径写得不一致**，另有一个要求项（Spring AI）后端做了但**前端根本没接**。

⚠️ **为什么现在跑起来看不出问题**：前端 `.env.development` 与 `.env.production` **都**是 `VITE_USE_MOCK=true`，
即前端默认走内置 Mock 数据、根本不请求后端。所以上述缺口只有在把 `VITE_USE_MOCK` 改为 `false`
、真实联调时才会集中暴露——**答辩/验收时一旦切真实后端，会大面积报错**。

## 三、问题清单

### 🔴 P0：路径不一致 —— 商品详情页必挂

| 前端调用 | 后端实际提供 |
|---|---|
| `GET /api/goods/{id}`<br/>（`api/goods.ts:101`，`fetchGoodsDetail`） | `GET /api/goods/{id}/detail`<br/>（`GoodsController.java:42`） |

后端**没有** `GET /goods/{id}` 映射，前端请求会直接 **404**。商品详情页是核心页面，
所有入口（列表点进详情、我的发布→查看、收藏→查看）都会失败。

**修复方案（二选一，推荐第一个）**：
1. 后端加一个别名映射，保持前端不动：
   ```java
   @GetMapping({"/goods/{id}/detail", "/goods/{id}"})
   public Result<Goods> fetchDetail(@PathVariable Long id) { ... }
   ```
2. 或者改前端 `api/goods.ts:101` 为 `url: \`/goods/${id}/detail\``。

### 🟠 P1：数据分析大屏缺 3 个接口（后端**没有 AnalyticsController**）

| # | 前端调用 | 前端位置 | 功能影响 |
|---|---|---|---|
| 13 | `GET /analytics/trend` | `api/analytics.ts:16` | 数据大屏趋势折线图 |
| 14 | `GET /analytics/category-distribution` | `api/analytics.ts:24` | 分类占比饼图 |
| 15 | `GET /analytics/top-goods` | `api/analytics.ts:32` | 热门商品排行榜 |

**佐证这是"规划了没做"**：
- 后端有 `AnalyticsService`，但只被 `AdminController` 用于 `/admin/overview`、`/admin/dashboard/summary`、
  `/admin/audit-logs`、`/admin/settings`；**没有 `AnalyticsController`**。
- `WebMvcConfig` 的白名单里**已经放行了 `/analytics/**`**（当成公开接口），
  但后端并不存在这些路径 —— 属于**悬空配置**，也反证了这些接口原本规划在 `/analytics/*`。

**修复方案**：新增 `AnalyticsController`，把已白名单的 3 个路径补上（白名单可保持不动）。

### 🔵 P2：Spring AI 后端做了，前端完全没接

| 后端接口 | 前端引用 |
|---|---|
| `POST /api/ai/generate-description`（商品描述自动生成） | **0 处** |
| `POST /api/ai/chat`（智能客服） | **0 处** |

在前端整个 `src/` 中搜索 `/ai/`、`generate-description`、`aiChat` 等关键字**均无命中**，
界面上也没有任何 AI / 智能助手入口。

**影响**：要求 2-(1)「Spring AI」在后端代码层面是完整的（依赖、配置、Service、Controller 齐全），
但**从系统角度看该功能不可达** —— 用户点不到、也没页面调用它，答辩演示时无法展示。

**修复方案（任选）**：
1. 在发布商品页「描述」输入框旁加一个「AI 生成描述」按钮 → 调 `POST /ai/generate-description`；
2. 在站点右下角加一个「智能客服」悬浮入口 → 调 `POST /ai/chat`；
3. 前端新增 `src/api/ai.ts` 封装上述两个接口，再接入上述 UI。

## 五、比对方法与可复现性

- 前端端点数取自 `src/api/*.ts` 中所有 `request({ url, method })`（已排除 `*.spec.ts`），
  路径参数（`` `${id}` `` / `{id}`）统一归一化为 `{}` 后比较 **方法 + 路径**。
- 后端端点数取自 `controller/*.java` 的 `@RequestMapping`（类级前缀，仅 `AiController` 有）
  与 `@Get/Post/Put/Delete/PatchMapping`（方法级）的组合。
- 已排除脚本误判：`api/user.ts:571` 使用了三元表达式
  （`url: addr.id ? \`/user/addresses/${addr.id}\` : '/user/addresses'`），
  该行对应的 `POST/PUT /user/addresses` 后端**已有实现**，非缺陷。

> ⚠️ 本节的比对脚本 v1 本身有 4 处漏抓/误判（数组形式注解、三元 url、三元 method、
> 笛卡尔积伪缺口），已迭代到 v3。完整脚本与踩坑记录见
> **《前后端接口比对脚本》**（`docs/前后端接口比对脚本.md`，可执行文件
> `docs/compare-endpoints.js`）。**上述「16 个未实现」是 v1 修正后的结论，已逐条复验无误。**
