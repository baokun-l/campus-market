## 「检查一下还有什么问题全部修改完善」—— 安全与健壮性体检（同日晚）

上文把**接口契约**补齐了（MISSING=0）。本轮通读业务代码，发现的问题**全部落在契约之外**：
接口对得通、Mock 也过得去，但切真实后端后**一条 curl 就能打穿**。
产出报告：`campus-secondhand-backend/docs/后端安全与健壮性体检报告.md`

### P0（越权 / 提权，3 项）
1. **`/admin/**` 只验登录不验角色** → 任意学生可 `POST /admin/users/{id}/reset-password` **接管他人账号**、
   `PATCH /admin/settings` 改平台配置、`DELETE /admin/audit-logs` **抹审计痕迹**、批量删商品、伪造退款。
   前端 `meta.requireAdmin` 只是路由守卫，绕过页面直连即失效。
   修复：`AuthInterceptor` 内新增角色分区（`/review/goods/**`→admin|goods_admin；
   `/admin/reports/**`→admin|report_admin；其余 `/admin/**`→仅 admin）。
   **判定顺序必须「先审核子域、后 /admin/** 兜底」**，反了 report_admin 会被自己后台挡在门外。
2. **`DELETE /goods/{id}`、`PATCH /goods/{id}/status` 无归属校验**：
   `GoodsService` 里**已有** `requireOwner` 重载，但 Controller 调的是**不带 operatorId 的那个**，校验形同虚设。
   修复：Controller 传 `currentUserId/currentRole`；`requireOwner` 加角色参数（后台角色放行）；
   无 operatorId 重载标注「仅供系统内部联动」防再次误用。
3. **`POST /reviews` 全采信请求体**：可拿别人订单号刷评价、把 `toUserId` 填成任意人**刷差评**（星级进信誉分）、
   `rating` 传 null 时 `Math.max(1,null)` 拆箱 **NPE→500**。
   修复：以订单为准 —— 校验当事人、goodsId 取订单值、**toUserId 由订单推导**、状态须 completed、rating 兜底。

### P1（完整性 / 撤权不干净，4 项）
4. **封禁与降权撤不干净**：角色/状态全取自 JWT 快照。封禁后对方**旧 token 到期前照样畅通**；降权后旧 token 里 role 仍是 admin。
   修复：已登录请求**回查 `t_user`**，用库里 status/role 覆盖快照；封禁 → 回 401（前端会清 token 跳登录）。
5. **`POST /orders/{id}/review/append` 无发起人参数** → 任何人可替别人追评。修复：签名加 userId/role。
6. **可购买自己发布的商品**（前端详情页也没藏自己的「立即购买」）→ buyerId==sellerId 时两套越权判定同时成立，且**自买自卖刷 GMV**。
   修复：`createOrder` 加自购拦截。**属行为变更**，已向用户明示。
7. **库存扣减非原子**（读-改-写）→ 并发抢最后一单**超卖**。修复：条件原子扣减 `stock = stock - qty where stock >= qty`，
   受影响行数 0 即库存不足；售罄置 sold 放扣减后重读再判（不拼方言 `IF()`）。

### P2（健壮性 / 信息泄露，4 项）
8. **认证失败返回 HTTP 401/403 → 前端两条分支成死代码**：后端所有业务错误都是「HTTP 200 + body code」，
   而拦截器写 HTTP 401/403，axios 把非 2xx 丢进 error 分支、只认 404/≥500/网络错误 → 弹「Request failed with status code 401」英文乱码。
   即**token 过期从未真正触发过「重新登录」弹窗**（改造前就存在的隐藏 bug）。
   修复：拦截器统一改为 HTTP 200 + body 业务码。
9. **兜底异常把 `e.getMessage()` 直吐前端**（SQL 片段/表名/NPE 行号）→ 改「日志记全量、响应给通用文案」。
10. **参数错误被当 500**：`GET /orders/abc/logs`、非法 JSON 原先都落到兜底 → 新增
    `MethodArgumentTypeMismatchException`(1001) / `HttpMessageNotReadableException`(1001) / `NoResourceFoundException`(404)。
11. **密码明文存储 + 凭据硬编码**：
    - 接入 **BCrypt**，只加 `spring-security-crypto`（**不引 spring-boot-starter-security**，避免 Filter 链接管现有 JWT 路由）。
    - **双模式兼容**（关键决策）：`$2a$/$2b$/$2y$` 开头按 BCrypt 校验；历史明文按明文比对，**通过后顺手升级为哈希**。
      → 老账号登录一次自动收敛、**无需手工迁移**，`schema.sql` 种子账号 `admin/admin123` 仍可直接登录，演示零改动。
    - `application.yml` 数据源与 JWT 改 `${ENV:默认值}`（`DB_URL/DB_USERNAME/DB_PASSWORD`、`JWT_SECRET/JWT_EXPIRATION`）。
    - 顺带修 `user.getPassword().equals(password)` 在列值为空时的 NPE。

## 后端修复（错误码语义 + AI 降级）
- **核心**：`BusinessException.of(String)` 单参构造的默认码是 `SERVER_ERROR(500)`，
  导致 **21 处**业务规则拒绝（库存不足/不能自购/重复审核/密码错误…）全被报成「服务端故障」。

  意义：修复前一个用户输错密码就能在日志里造 error 级堆栈，真实故障被淹没。
- 逐点语义化：不存在类 → `notFound()`(404)；封禁 → `forbidden()`(403)；密码错误 → `paramError()`(1001)。
  ⚠️ **密码错误刻意避开 401**：前端对 401 是「弹登录过期 + 清 token + 跳 /login」的全局处理，
  登录页输错密码若返 401 会弹出语义错乱的过期提示。

  `IllegalArgumentException` —— 它们会落到兜底分支，**响应文案被脱敏成「服务器内部错误」**，
  真实原因（公告不存在 / 批量动作不支持）直接丢失。
- **AI 接口会 500 且要等 21 秒**：默认 `api.openai.com` 国内 **连接超时**
  （`ConnectException: Connection timed out`），Spring AI 还叠加重试。

  ② `spring.ai.retry.max-attempts: 1`；③ 新增 `config/AiHttpClientConfig` 提供带超时的
  `RestClient.Builder`（3s 连接 / 8s 读）—— Spring AI M6 **没有暴露 openai 超时配置项**，
  但 `OpenAiAutoConfiguration#openAiChatModel` 签名里有 `ObjectProvider<RestClient.Builder>`，
  **自建该 Bean 就会被采用**。
  实测：**21s / code=500 → 3.0s / code=0**。

## 6. 本机环境**新增**的坑（第三轮）
1. **PowerShell 工具的 stdout 捕获会吞输出**：`Format-Table | Out-String`、`$out -join` 直接输出
   常常返回空（exit 0 无内容）。**可靠做法：写文件再读**（`Set-Content -Encoding UTF8` + Read 工具）。
2. **`*>` 重定向写出的是 UTF-16**，Read 工具会报 `Cannot display content of binary file`。
   改用 `($out | Out-String) + "`nexit=$code" | Set-Content -Encoding UTF8`。
   而 `Out-File -Encoding UTF8` 仍会在控制台显示乱码（PS5.1 写 UTF8 但控制台按 ANSI 回显）——
   **乱码不代表文件内容错**，以 Read 工具读到的为准。
3. **bash 的 coreutils 本轮彻底不可用**（`ls/grep/sed/head/dirname` 全 `command not found`，
   PATH 指向的 PortableGit 缺这些二进制）。**改用 Grep/Glob/Read 专用工具**；
   `curl` 仍可用（独立二进制）。
4. **`curl` 访问本地端口返回 502 而不是连接拒绝**：因为 WorkBuddy 给子进程注入了
   `HTTP_PROXY/HTTPS_PROXY`（系统代理残留，指向 Nano 的 65532）。判断「端口没服务」时别信这个 502。
   同理 `Invoke-WebRequest` 也可能受影响，本轮的探测改用 `127.0.0.1` 直连 + 显式端口。
