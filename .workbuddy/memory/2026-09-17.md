### ★ 关键坑（差点踩死）：`-s` 覆盖不了 global settings 的 localRepository

两份 3.8.4 的 `conf/settings.xml` **都是**（从同一个包拷的）：
```xml
<localRepository>C:\Program Files\Java\apache-maven\respository</localRepository>
```
而该目录 **无写权限** —— 实测 `New-Item` 报 `对路径的访问被拒绝`（Program Files 默认 ACL）。
Maven 往里写依赖必然 `Access Denied`。

**最容易误判的点**：以为「用 `-s 自己的settings.xml` 就能绕开」—— **不行**。
Maven 会把 global settings（安装目录 `conf/settings.xml`）与 `-s` 指定的 settings **合并**，
global 里那行 `localRepository` **依然生效**；**只有显式声明的项才会被覆盖**。
（`-s` 是"替换 user settings"，不是"替换 global settings"。）

**解法**：在 `.workbuddy/mvn-aliyun-settings.xml` 里**显式**加一行
`<localRepository>D:\apache-maven-3.9.4\mvn_repo</localRepository>`
（放在 `<mirrors>` **之前**，XSD 要求 localRepository 排在 mirrors 前面）。
该仓库已缓存全套 Spring Boot 3.2.5 / Spring AI M6 依赖 → **零下载**。

同文件注释里已把这套原因写清，并补了「用 D 盘 Maven」的完整构建命令。

### 4) ★ 本轮最耗时的坑：一条「假失败」，根因在测试脚本不在后端

`e2e-p1-8-orders.mjs` 最初 96 PASS / **1 FAIL**：`显式 statuses 白名单原样生效 — total=undefined`。

排查结论（写了个 `probe-statuses.mjs` 单点探针才确认）：

| 形态 | 结果 |
|---|---|
| `statuses[]=pending`（**Node fetch 原始方括号**） | **HTTP 400 + HTML 错误页**（Tomcat 拒绝请求行里的原始 `[` `]`） |
| `statuses%5B%5D=pending`（**浏览器/axios 真实形态**） | 200 / `total=1` / `statuses=pending` ✅ |
| `statuses=pending`（裸名） | 200 ✅ |
| `statuses=pending,off_shelf`（CSV） | 200 ✅ |

**浏览器（XHR/fetch）会自动把 `[` `]` 编码成 `%5B%5D`，Node 的 `fetch` 走 WHATWG URL 不编码。**
所以真实前端流量没问题，是测试脚本没照抄编码。已在脚本里改成 `%5B%5D` 并写了注释。
**教训：用 Node 脚本测带方括号的查询参数，必须自己编码。**
